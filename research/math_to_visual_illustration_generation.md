# Research: Material Generation from Math to Visual Illustration

**Research Date:** 2025-11-09
**Context:** Educational Agent Framework - Material Generation Feature

## Executive Summary

This document presents comprehensive research on generating visual educational materials from mathematical concepts, covering state-of-the-art models, approaches, and implementation strategies for the mini_agent educational framework.

### Key Findings

1. **Multiple complementary approaches** exist: code-based (SVG/TikZ), raster image generation (diffusion models), animation (Manim), and interactive tools (GeoGebra/Desmos)
2. **Recent breakthroughs** (2024-2025) in LLM-based diagram generation show promise, particularly for SVG and vector graphics
3. **Multimodal models** (GPT-4V, Claude 3.5, Gemini) excel at understanding mathematical diagrams but struggle with generation
4. **Hybrid approaches** combining LLMs for code generation + rendering engines produce the best results
5. **Current limitations** include difficulty with complex geometric figures and precise mathematical notation

## Approaches to Math-to-Visual Generation

### 1. Code-Based Vector Graphics Generation

#### SVG Generation via LLMs

**Recent Research:** "From Text to Visuals: Using LLMs to Generate Math Diagrams with Vector Graphics" (March 2025)

**Key Findings:**
- LLMs can generate SVG code from textual descriptions of mathematical diagrams
- Uses GPT-4o for both generation and evaluation
- Intermediate SVG representation allows for precise, scalable diagrams
- VQA (Visual Question Answering) used for automated evaluation

**StarVector Model (2024):**
- Foundation model transforming vectorization into code generation
- Vision-language architecture processes visual and textual inputs
- Produces high-quality SVG code for icons, diagrams, graphs, and charts
- Available on HuggingFace: `starvector/starvector-8b-im2svg`

**LLM4SVG (CVPR 2025):**
- Designed to understand SVG semantics and generate structured representations
- Limitation: ChatGPT and GPT-4 struggle with complex graphics, only excel at simple primitives

**Evaluation Framework - VGBench (EMNLP 2024):**
- First comprehensive vector graphics benchmark
- 4,279 multi-choice QA pairs + 5,845 VG-caption pairs
- Tests understanding and generation across diverse VG types

#### TikZ/LaTeX Code Generation

**Current Capabilities:**
- GPT-4 and Claude 3 can generate TikZ code for mathematical diagrams
- Best for geometric figures, flowcharts, technical diagrams
- Chain-of-thought prompting significantly improves quality

**DeTikZify (NeurIPS 2024):**
- Specialized model for generating TikZ programs from images
- GPT-4V achieved AVG score of 0.612
- Claude 3 trails behind specialized models
- Proprietary chatbots mix code and natural language, affecting effectiveness

**Practical Tools:**
- GeoGebra can export to TikZ
- Prompt engineering guides available for GPT-4/Claude
- TikZ LaTeX Expert GPT available on TAAFT

### 2. Raster Image Generation (Diffusion Models)

#### DALL-E 3 (OpenAI)

**Architecture:**
- Text-to-image diffusion model
- GPT-4 integration for prompt refinement
- Synthetic captions generated by GPT-4V during training

**Educational Applications:**
- Excellent for explanatory diagrams and editorial illustrations
- Text rendering capabilities improved
- Natural language refinement ("add a walrus")
- Works well for schematic/assembly/evolutionary diagrams

**Limitations:**
- Less precise than vector graphics for mathematical notation
- Not editable after generation
- May struggle with exact geometric properties

#### Stable Diffusion 3 (2024)

**Architecture Updates (March 2024):**
- Switched from UNet to Transformer model
- Latent diffusion architecture
- Fine-tuning capability for specialized domains

**Educational Use Cases:**
- Scientific visualization
- Historical reconstruction
- Fine-tunable for domain-specific content

#### Other Diffusion Models (2024)

- **Imagen 3** (Google, May 2024)
- **Stable Video 4D** (July 2024) - for 3D object videos
- **Midjourney** - professional illustration quality

**Mathematical Foundations:**
- Markov chain noise addition + neural network denoising
- Variance schedule during training
- Iterative denoising from random noise

**Capabilities:**
- Precise control over animation timing and transitions
- Excellent for explaining mathematical concepts visually

**Requirements:**

- Available on PyPI and GitHub

**Recent Development - Manimator (2025):**
- "Transforming Research Papers and Mathematical Concepts into Visual Explanations"
- Automates creation of Manim animations from mathematical content

## Technical Implementations

### Unified Multimodal Framework Architecture

**Three Core Components (2024-2025 Research):**

1. **Modality-Specific Encoders**
   - Project different input modalities into unified representation space
   - Vision encoders: CLIP, InternVL, Qwen-VL
   - Text encoders: BERT, GPT, LLaMA variants

2. **Modality-Fusion Backbone**
   - Integrates information from multiple modalities
   - Enables cross-modal reasoning
   - Architectures: Transformers, cross-attention mechanisms

3. **Modality-Specific Decoders**
   - Generate output in desired modality
   - Text generation: Autoregressive models
   - Image synthesis: Diffusion models, VAEs
   - Code generation: Fine-tuned language models

### Implementation Patterns

#### Pattern 1: LLM → Code → Render

```
User Request (Text)
    ↓
LLM (GPT-4, Claude) generates code
    ↓
Code (SVG, TikZ, Python/Matplotlib, Manim)
    ↓
Rendering Engine
    ↓
Visual Output (PNG, SVG, Animation)
```

**Advantages:**
- Precise, editable output
- Reproducible results
- Version control friendly
- Parameterizable

**Use Cases:**
- Mathematical diagrams
- Technical illustrations
- Animated explanations
- Interactive visualizations

#### Pattern 2: LLM → Diffusion Model → Raster Image

```
User Request (Text)
    ↓
LLM refines prompt (GPT-4)
    ↓
Diffusion Model (DALL-E 3, Stable Diffusion)
    ↓
Raster Image (PNG, JPG)
```

**Advantages:**
- Natural, artistic style
- Good for conceptual illustrations
- Quick generation

**Limitations:**
- Not editable
- Less precise
- Hard to enforce exact properties

#### Pattern 3: Interactive Tool Integration

```
User Request or Constraints
    ↓
GeoGebra/Desmos API
    ↓
Interactive Diagram + Export
```

**Advantages:**
- User manipulation
- Dynamic exploration
- Multiple export formats

- Fine-grained error analysis

**Key Results:**
- GPT-4V: best closed-source performance
- MAVIS-7B: best open-source performance

- ShareGPT4V shows relatively better visual comprehension

**Dataset:**
- HuggingFace: AI4Math/MathVerse
- Testmini: 788 problems across 5 versions
- Official leaderboard available

**Focus:** Mathematical perception in MLLMs

**Benchmark Design:**
- 1.2K images
- 1.6K carefully curated questions
- Four perception tasks:

**Key Finding:**
- MLLMs struggle with abstract visual representations
- Precise geometric structures challenge current models
- Symbolic notation interpretation needs improvement

### Proposed Architecture

#### Layer 1: Content Strategy Selector

```python
class MaterialGenerationStrategy(Enum):
    VECTOR_CODE = "vector_code"  # SVG, TikZ via LLM
    RASTER_IMAGE = "raster_image"  # DALL-E, Stable Diffusion
    INTERACTIVE = "interactive"    # Desmos, GeoGebra
    ANIMATION = "animation"        # Manim
    PLOT_CODE = "plot_code"        # Matplotlib, Plotly
```

**Decision Logic:**
- Geometric diagrams → VECTOR_CODE (TikZ, SVG)
- Conceptual illustrations → RASTER_IMAGE
- Graphs/data → PLOT_CODE
- Explorations → INTERACTIVE
- Step-by-step explanations → ANIMATION

```python
class AdaptiveMaterialGenerator:
    """Integrates with knowledge graph and student profiling"""

    def __init__(self,
                 knowledge_graph: KnowledgeGraph,
                 student_profiler: StudentProfiler):
        self.kg = knowledge_graph
        self.profiler = student_profiler
        self.generators = {
            MaterialGenerationStrategy.VECTOR_CODE: VectorCodeGenerator(),
            MaterialGenerationStrategy.PLOT_CODE: PlotCodeGenerator(),
            MaterialGenerationStrategy.RASTER_IMAGE: RasterImageGenerator(),
            MaterialGenerationStrategy.INTERACTIVE: InteractiveDiagramGenerator(),
            MaterialGenerationStrategy.ANIMATION: AnimationGenerator(),
        }

    async def generate_personalized_material(self,
                                            concept_id: str,
                                            student_id: str,
                                            material_type: str) -> Material:
        # 1. Retrieve concept from knowledge graph
        concept = await self.kg.get_concept(concept_id)

        # 2. Get student profile
        profile = await self.profiler.get_profile(student_id)

        # 3. Select strategy based on concept type and student preferences
        strategy = self._select_strategy(concept, profile, material_type)

        # 4. Generate material
        generator = self.generators[strategy]
        material = await generator.generate(concept, profile, constraints)

        # 5. Evaluate and potentially iterate
        evaluation = await MaterialEvaluator().evaluate(material, concept, profile)
        if evaluation.score < threshold:
            material = await MaterialEvaluator().iterate_if_needed(material, evaluation)

        # 6. Store in memory system
        await self.memory.store_material(material, concept_id, student_id)

        return material
```

## Best Practices & Lessons Learned

### Prompt Engineering for Diagram Generation

**For TikZ/SVG Code:**
```
You are an expert mathematical illustrator. Generate TikZ code for [CONCEPT].

Requirements:
- Use precise coordinates
- Label all important points
- Use appropriate colors and line styles
- Include a coordinate system if relevant
- Comment the code for clarity

Mathematical constraints:
[SPECIFIC PROPERTIES FROM CONCEPT]

Output ONLY the TikZ code, no explanations.
```

**For DALL-E 3:**
```
Generate a schematic diagram showing [CONCEPT].

Style: Educational textbook illustration
Requirements:
- Clear labels
- High contrast
- Simple, clean lines
- Mathematical accuracy
- [SPECIFIC PROPERTIES]

The diagram should help students understand [LEARNING OBJECTIVE].
```

### Evaluation Strategies

**Multi-Level Evaluation:**

1. **Syntactic:** Does code execute without errors?
2. **Semantic:** Are mathematical properties correct?
3. **Pedagogical:** Does it help learning?
4. **Aesthetic:** Is it clear and appealing?

**Use VQA for Verification:**
```python
async def verify_diagram(image: Image, concept: Concept) -> bool:
    prompt = f"""
    This diagram should illustrate {concept.description}.

    Verify:
    1. Are all labeled elements correct?
    2. Are mathematical relationships accurate?
    3. Is it pedagogically clear?

    Answer with JSON: {{"correct": bool, "issues": [str]}}
    """

    result = await gpt4v.analyze(image, prompt)
    return result["correct"]
```

### Handling Failures

**Graceful Degradation:**
1. Try primary method (e.g., TikZ)
2. If fails, try alternative (e.g., SVG)
3. If fails, try raster (e.g., DALL-E)
4. If fails, return text description with placeholder

**Error Recovery:**
- Parse error messages from code execution
- Use LLM to fix common syntax errors
- Implement retry with modifications (max 3 attempts)
- Cache successful patterns for reuse

### Performance Optimization

**Caching Strategy:**
- Hash: (concept_id, generation_strategy, parameters)
- Store: Generated code + rendered image
- TTL: Based on concept stability
- Invalidation: On concept updates

**Parallel Generation:**
- Generate multiple formats concurrently
- Use async/await extensively (already in codebase!)
- Stream results as they complete

**Cost Optimization:**
- Use cheaper models for initial generation (GPT-3.5)
- Use GPT-4 only for evaluation and refinement
- Cache expensive operations
- Batch similar requests

## Conclusion

Material generation from mathematical concepts to visual illustrations is a rapidly evolving field with multiple viable approaches:

1. **Code-based generation (Recommended)** offers precision, editability, and reproducibility
2. **Diffusion models** provide quick conceptual illustrations
3. **Interactive tools** enable exploration and engagement
4. **Animation** supports step-by-step understanding

For the **mini_agent** educational framework, a **hybrid approach** is recommended:
- Use **LLM → Code → Render** pipeline as primary method
- Supplement with **diffusion models** for conceptual art
- Integrate **interactive tools** for exploration
- Consider **animations** for complex explanations

The existing infrastructure (LiteLLM, async architecture, knowledge graphs) provides an excellent foundation. Implementation can proceed incrementally through the proposed 6-8 week roadmap, starting with plot generation and progressively adding more sophisticated capabilities.

**Key Success Factors:**
- Strong prompt engineering for each generation type
- Multi-modal evaluation using GPT-4V/Claude 3.5
- Iterative refinement based on educational goals
- Integration with student profiling for personalization
- Robust caching and error handling

The research shows this is technically feasible with current models, particularly GPT-4, Claude 3.5, and specialized tools like StarVector for SVG generation.
